Cocktail : Observatoire des tendances sur X et Bluesky

Stage de 4 mois - 2025

Remise en état du projet cocktail

Stage Rust API PostgreSQL Data Pipeline Web Scraping

Contexte du projet

J'ai contribué au développement de Cocktail, une plateforme web destinée à analyser les tendances et discours émergents sur les réseaux sociaux X et Bluesky. Ce projet s'inscrit dans un contexte de Recherche, co-financé par l'union européenne, avec pour objectif de fournir aux chercheurs un outil d'analyse réactif et accessible.

Technologies utilisées

Backend & Collecte

  • Rust - Développement et gestion du backend
  • API X/Twitter & Bluesky - Récupération des données
  • PostgreSQL - Stockage et traitement des données

Outils & Méthodologie

  • GitHub - Versionning
  • CSV Parsing - Importation de données
  • Machine virtuelle (WSL) - Environnement de test

Missions initiales du stage

Réinstallation de la plateforme

Défi : Transférer la plateforme Cocktail depuis les serveurs d'ATOL CD vers les serveurs de l'Université de Bourgogne. Nous avons récupéré le code via des dépôts Git, travaillé en local pour comprendre et améliorer le système, puis effectué le déploiement final.

Adaptation à la nouvelle API de X

Problème critique : La plateforme utilisait l'ancienne version de l'API X (avant v2), empêchant toute collecte de données. Les nouvelles limitations nécessitaient un compte chercheur professionnel, que nous avons dû attendre longtemps.

Nouvelles fonctionnalités

Évolution : Développement de fonctionnalités d'import/export CSV (pour faciliter les tests et réutiliser des données passées) et création de nouveaux systèmes de tri et visualisation suite aux échanges avec notre maître de stage.

Amélioration parcours utilisateur

Objectif : Rendre la plateforme suffisamment intuitive pour permettre aux chercheurs d'exploiter les données après configuration des requêtes nécessaires, sans intervention technique.

Problématique de l'ancien système :

  • Outil de collecte Garuda (Scala) séparé et peu pratique
  • Opérations manuelles en ligne de commande sur le serveur
  • Arrêt/redémarrage des services pour chaque import
  • Processus accessible uniquement aux développeurs experts
  • Lenteur incompatible avec l'analyse en temps réel

Solutions développées

Nouvel outil de collecte en Rust

Suppression complète de l'ancien outil Garuda (Scala) et développement d'un nouveau module intégré directement dans Cocktail. Collecte désormais possible sur X et Bluesky avec une interface utilisateur unifiée.

Documentation complète

Création d'une documentation exhaustive pour un projet initialement non documenté : procédures d'installation, commentaires de code, schémas d'architecture, et guides utilisateur.

Import/Export CSV

Développement de fonctionnalités permettant d'importer des données existantes (pour tests et réutilisation) et d'exporter les résultats d'analyses pour exploitation externe.

Nouvelles interfaces de tri

Création d'interfaces utilisateur pour le tri et la visualisation des données, permettant aux chercheurs de manipuler facilement les résultats de collecte.

Tests robustes multi-plateforme

Validation approfondie des APIs X et Bluesky, tests avec fichiers CSV réels pour gérer les cas limites et formats variés, environnement de test sécurisé.

Déploiement université

Installation réussie de la plateforme sur les serveurs de l'Université de Bourgogne, avec configuration des droits d'accès et procédures de maintenance.

Défis techniques relevés

Montée en compétence autonome

J'ai appris Rust en autonomie pour remplacer une application Scala existante, en analysant le code source et développant de nouveaux modules adaptés.

Reverse engineering

Face à l'absence totale de documentation, j'ai exploré méthodiquement le code source, créé un environnement de test et documenté mes découvertes.

Validation d'APIs et migration

Tests approfondis de l'API Bluesky et adaptation critique de l'API X (migration v1 vers v2) qui empêchait complètement la collecte. Compréhension des formats, limites de fréquence et gestion des comptes professionnels requis.

Veille technique constante

Recherche intensive de bibliothèques Rust à jour et adaptées au projet, exploration de solutions pour contourner les limitations d'API, et évaluation de nouvelles technologies pour optimiser les performances.

Défis organisationnels

Autonomie totale sans encadrement technique

Mon binôme et moi étions seuls dans un bureau sans personne pour nous aider ou nous conseiller sur nos choix techniques. Nous avons dû développer notre capacité d'autoformation et de prise de décision en équipe.

Navigation dans l'incertitude

Nous n'avions que les objectifs initiaux pour nous guider, sans cahier des charges ni documentation. Les fonctionnalités à développer se précisaient au fur et à mesure des échanges avec notre maître de stage, nous forçant à être flexibles.

Gestion de projet sur 4 mois

Planification autonome des tâches pour éviter de "s'emmêler les pinceaux" et optimiser notre efficacité. Répartition claire du travail entre binômes et établissement d'un plan d'action structuré.

Communication avec les non-initiés

Nécessité d'expliquer constamment les tenants et aboutissants de chaque problème technique et solution à notre maître de stage, qui n'était pas expert en informatique. Développement de notre capacité de vulgarisation.

Ce que ce projet m'a apporté

Compétences techniques

  • Maîtrise du Rust : Apprentissage autonome d'un nouveau langage pour remplacer une application Scala
  • Architecture web : Compréhension approfondie des applications web (backend, routes, autorisations d'accès)
  • Gestion d'APIs : Maîtrise des APIs X et Bluesky, pipelines de données en temps réel
  • Administration système : Déploiement sur serveurs universitaires, gestion des droits d'utilisation

Soft skills et autonomie

  • Autonomie renforcée : Recherche de solutions à des problèmes inconnus sans encadrement technique
  • Gestion de projet long terme : Planification sur 4 mois, répartition des tâches en binôme
  • Communication technique : Capacité à expliquer des concepts complexes aux non-initiés
  • Travail en équipe : Collaboration efficace et communication avec les supérieurs

Méthodologie et rigueur

  • Veille technique : Recherche et évaluation de bibliothèques et technologies adaptées
  • Reverse engineering : Analyse de code non documenté pour comprendre l'architecture existante
  • Rigueur de développement : Structuration du projet pour optimiser le développement
  • Adaptabilité : Navigation dans des objectifs flous et évolutifs

Vision produit

  • Orientation utilisateur final : Création d'outils simples et utiles pour les chercheurs
  • Analyse des besoins : Évolution du projet selon les retours utilisateurs
  • Documentation : Création de guides pour assurer la pérennité du projet

Ce stage de 4 mois m'a permis de développer une approche méthodique et autonome face à des défis techniques et organisationnels complexes. J'ai appris à naviguer dans l'incertitude tout en maintenant une vision orientée utilisateur, créant des outils réellement utiles aux chercheurs. L'expérience m'a particulièrement renforcé dans ma capacité à gérer un projet sur le long terme et à communiquer efficacement avec des non-experts en informatique.
